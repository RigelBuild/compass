# Reload held control ops

Tracker: RIG-3923. Freezes on merge.

Depends on the reload replay barrier record (`docs/designs/agent/reload-replay-barrier/design.md`, DL-372), which makes `reloadLocked` re-send `AgentControl{replay_complete}` after the stream swap. This record does not restate it.

## Problem / Intent

`reloadLocked` in `go/internal/runner/host.go` SIGKILLs the running agent (`s.stream.Stop()`) and relaunches one into the same session. A live op the old agent received but never acked stays retained above the cursor, and `controlProducer.serve` in `go/internal/runner/gateway/control.go` starts every new subscription there: `sent := s.cursor` ("everything retained above it is owed to this subscription, whether it was never sent or sent to a predecessor that never acked"). The DL-372 lift carries the highest seq and `collectBatch` walks `s.ops` ascending, so the retained ops drain first, into the replacement's closed barrier. `dispatch` in `packages/compass-agent/src/transport/control-source.ts` refuses and acks each one ("live immediate op before ReplayComplete — refused by replay barrier", then `acks.markApplied(seq)`); the replacement's cursor is `0`, so the ack names the seq in `applied_above` and `AckControl` prunes it there (`if _, applied := above[r.seq]; applied { continue }`). The agent counts the refusal (`controlUnmapped`, plus `console.error` in `defaultOnUnmapped`); the Runner logs nothing. Deliver and forge ops stay owed on the Server's durable cursor (`DispatchControl`: "success rides a later delivery_ack") until the next session-start sweep (`OnSessionStarted`), which a long-lived session may never reach; a steer has no backstop.

## Approach

**Hold.** Raise the producer's existing replay barrier from `reloadLocked`, after `s.stream.Stop()` returns and before `h.link.StartAgent`, on served containers only. `controlProducer.HoldForReplay` was built for this ("Raised by the lifecycle when it restarts an agent into an existing session ... No production caller yet"). While `s.held` is set, `collectBatch` skips live ops (`if s.held && !replayPath(r.op) { continue }`) and `send` still wakes the drainer for the lift (`if !s.held || replayPath(stamped) { s.signalLocked() }`), so the lift drains through the hold and the retained ops follow in seq order after release. The hold precedes `StartAgent` because the lift is sent after it returns, so the replacement can subscribe before the lift exists. It reaches the producer through a new `SocketListener.HoldForReplay`, nil-safe like `BindSession`, resolved under `h.mu` and called outside it as the DL-372 helper does.

**Release is keyed to the lift.** `send` records `s.liftSeq = s.nextSeq` when `isLift(stamped)`, a new predicate true only for `AgentControl_ReplayComplete`; `HoldForReplay` clears it. `replayPath` also matches `AgentControl_Replay`, which the agent acks at decode (`case "replay": ... acks.markApplied(seq)`), so keying on it would release before the lift; `replayPath` keeps the barrier skip and the cap exemption. The hold releases only in `AckControl`, when `s.held && s.liftSeq != 0` and the ack covers the lift: `s.liftSeq <= s.cursor` or `above[s.liftSeq]` is present. The lift's seq did not exist before the hold, so no predecessor ack can name it; `liftSeq != 0` stops an ack read before the lift is sent from matching `0 <= s.cursor`.

`ReleaseReplayBarrier`, the `ReplayCompleteAck` route (`Gateway.Publish` in `go/internal/runner/gateway/publish.go`: `case *compassv1internal.AgentFrame_ReplayCompleteAck: g.control.ReleaseReplayBarrier(sessionID)`), becomes a no-op: the frame carries no identity (`ReplayCompleteAckSchema, {}`), so a delayed predecessor ack and the replacement's are the same frame. It stays on `ControlRouter` so `Publish` keeps consuming the frame.

Latency is unchanged. The `control-source.ts` iterator emits both acks in one `next()` call, apply-then-ack: `if (applied.op.kind === "replayComplete") acks.emitReplayCompleteAck(); acks.markApplied(applied.seq);`. The replacement's cursor is `0` and the held ops sit below the lift, so the production ack is `ControlAck{acked_seq: 0, applied_above: [lift]}`: the `applied_above` arm is the primary path. It is re-emitted on redelivery (`dispatch`: `if (acks.isApplied(seq)) { ...; acks.markApplied(seq); return; }`), so a lift-ack batch that exhausts `PRIORITY_BATCH_RETRY_MS` ("counted definitively failed") still releases on the next Control reconnect.

**Bound.** No timer: one that released would resurrect the loss, and one that errored needs a control-lane liveness contract this record does not invent. The hold's lifetime is retention's. `Retire` (`delete(p.sessions, sessionID)` ... `s.ops = nil`, reached from `Stop` or `Remove`) drops held ops with the session. `maxRetainedOps = 4096` fails a live `Send` with `CodeResourceExhausted`, but a low-traffic session never reaches it. The hold changes one case: a lost lift-ack batch is harmless today and becomes held until the Control reconnect above. A `StartAgent` failure leaves the hold raised with no agent to serve, as today; on podman a retry fails at `s.stream.Stop()` (`ChildHandle.Terminate` in `go/internal/runtime/podman.go` ends in `return h.cmd.Wait()`, and a second `Wait` errors), so it never reaches the hold. `HoldForReplay` logs the raise and `AckControl` logs the release, so a wedged hold is visible without a timer.

## Alternatives considered

- **Re-sequence the lift below the retained ops, or re-stamp them above it.** `s.ops` is "ascending by seq; pruned on ack" and `collectBatch` binary-searches it; re-stamping changes the seq an in-flight `ControlAck` names and defeats `acks.isApplied(seq)` dedup.
- **Accept the loss.** DL-081 makes config refresh routine, so the Problem's loss recurs on every refresh. One call fixes it.
- **Hold in `Start` too.** `Bind` creates fresh state (`p.sessions[sessionID] = &controlSession{}`): nothing is retained and the lift is first (`TestFreshStartSendsReplayCompleteFirst`).
- **Agent-side: buffer pre-barrier immediate ops in `dispatch` instead of refuse-and-ack.** Invariant 1 is pinned in the agent, and a buffered late deliver would apply ahead of a future transcript replay.
- **Drain-time reorder alone: emit replay-path ops before live ops in `collectBatch`, no hold.** The replacement can subscribe before the lift is sent, so its first drain cycle has only live ops to emit. Holding before `StartAgent` is what closes that race.

## Global Constraints

- No proto, wire, or agent-side change. `HoldForReplay`, `ReleaseReplayBarrier`, `AckControl`, `serve`, and `collectBatch` keep their signatures.
- The hold is raised only on a served container, after `s.stream.Stop()` returns and before `h.link.StartAgent`; the listener is resolved under `h.mu` and called outside it. Placement in `reloadLocked` covers `Reload` and `refreshOneContainer`. A hold on an unbound or retired session is a no-op (`existingSession` returns false), neither checked nor logged by the host.
- Release rule: `AckControl` clears `held` when `s.held && s.liftSeq != 0 && (s.liftSeq <= s.cursor || above[s.liftSeq] present)`, where `liftSeq` is the seq of the last `AgentControl_ReplayComplete` `send` stamped (`isLift`, never `replayPath`) and `HoldForReplay` clears it. Nothing else clears `held`; `ReleaseReplayBarrier` is a no-op. Retained ops drain in ascending seq after the lift; nothing is re-stamped.
- No timer, retry, or new bound. A `StartAgent` failure after the hold returns the error and leaves the hold raised, matching today's failed-reload posture (`refreshOneContainer`: "Reload failed: do NOT advance the tracked version ... retries").
- The producer gains a logger through a new `Deps.Log *slog.Logger`; `newControlProducer` defaults nil to `slog.Default()` as `NewConsumer` does. Raise and release log at Info with `session_id`. No other logging change.
- No database, token, container, or transcript change.

## Open Questions

- **OQ-1, load-bearing, routed to the operator as RIG-4005: release on lift delivery instead of on ack?** Option A (this record): ack-gated — `held` clears on a `ControlAck` covering `liftSeq`. Option B: clear `held` in `serve`'s send loop once `sink.Send` succeeds for an `isLift` op, then `signalLocked()`; drop `liftSeq` and the `AckControl` change. B covers reload: the replacement's barrier opens at decode (`dispatch`: `case "replayComplete": { replayComplete = true; ...`) and `serve` sends in order on one stream, with no held-until-reconnect case. B's residual: a predecessor drainer that has not yet exited can `sink.Send` the lift on its dead stream and clear `held` before the replacement subscribes. A keeps the frozen protocol text in `packages/compass-agent/src/control.ts` ("the Runner holds live prompt/steer until the agent acks ReplayComplete"), which a future `TranscriptReplay` needs: its live ops must wait for apply, not decode. Recommendation: keep A; the plan above is A.
- **OQ-2, resolved — predecessor liveness at the hold.** "No agent alive after `Stop`" is inherited from `AgentStream.Stop` in `go/internal/runner/agent_exec.go` (`s.exec.Process.Terminate()`). It holds on the host tier (`HostRuntime.ExecStreaming` in `go/internal/runtime/host_backend.go`: `killGroup(proc.pgid, syscall.SIGKILL)`) and the microVM tier (`MicroVMRuntime.ExecStreaming` in `go/internal/runtime/microvm_lifecycle.go`: `gs.Kill(int(syscall.SIGKILL))`). On podman, `spawnStreaming` in `go/internal/runtime/clispawn.go` sets `cmd.Cancel = func() error { return cmd.Process.Kill() }`, which kills the `podman exec` client; the repo does not show whether the in-container agent dies with it. A survivor would ack the new lift and consume the held ops — today's zombie behavior, not a regression.
- **OQ-3, resolved — agent-side dedup.** The replacement's `AckCursor` starts at `#cursor = 0n`, so `acks.isApplied(seq)` is false for every held seq.
- **OQ-4, deferred — an agent that never acks the lift.** Held with the hold, refused without it. A liveness deadline for the control lane is a separate record.
