# Reload held control ops

Tracker: RIG-3923. Freezes on merge.

Depends on the reload replay barrier record (`docs/designs/agent/reload-replay-barrier/design.md`, DL-372), which makes `reloadLocked` re-send `AgentControl{replay_complete}` after the stream swap.

## Problem / Intent

`reloadLocked` in `go/internal/runner/host.go` SIGKILLs the running agent (`s.stream.Stop()`) and relaunches one into the same session. A live op the old agent received but never acked stays retained above the cursor, and `controlProducer.serve` in `go/internal/runner/gateway/control.go` starts every new subscription there (`sent := s.cursor`: "everything retained above it is owed to this subscription"). The DL-372 lift carries the highest seq and `collectBatch` walks `s.ops` ascending, so the retained ops drain first, into the replacement's closed barrier. `dispatch` in `packages/compass-agent/src/transport/control-source.ts` refuses and acks each one ("live immediate op before ReplayComplete — refused by replay barrier", then `acks.markApplied(seq)`); the ack names the seq in `applied_above` and `AckControl` prunes it. The agent counts the refusal; the Runner logs nothing. Deliver and forge ops stay owed on the Server's durable cursor (`DispatchControl`: "success rides a later delivery_ack") until the next session-start sweep (`OnSessionStarted`), which a long-lived session may never reach; a steer has no backstop.

## Approach

**Hold.** `reloadLocked` raises the producer's existing replay barrier (`controlProducer.HoldForReplay`, "No production caller yet") through a new nil-safe `SocketListener.HoldForReplay`, at the placement Global Constraints fixes. While `s.held` is set, `collectBatch` skips live ops (`if s.held && !replayPath(r.op) { continue }`) and `send` still wakes the drainer for the lift (`if !s.held || replayPath(stamped) { s.signalLocked() }`), so the lift drains through the hold and the retained ops follow after release. The hold precedes `StartAgent` because the lift is sent after it returns, so the replacement can subscribe first.

**Release is keyed to the lift.** The `ReplayCompleteAck` frame carries no identity (`ReplayCompleteAckSchema, {}`), so a delayed predecessor ack and the replacement's are the same frame; a `ControlAck` names seqs. `send` records `liftSeq` for each `AgentControl_ReplayComplete` it stamps, and `AckControl` clears `held` when an ack covers it (rule in Global Constraints). The lift's seq did not exist before the hold, so no ack emitted before the hold can name it, and where `Stop` kills the old agent (host, microVM) nothing else can; on podman and apple-container the pre-reload agent survives `Stop` (RIG-4029, below). `isLift` is a forward guard: `replayPath` also matches `AgentControl_Replay`, which the agent acks at decode (`case "replay": ... acks.markApplied(seq)`), but `representable` rejects it today (`case *compassv1internal.AgentControl_Replay, ...: return false`), so no sendable op separates the two predicates. `replayPath` keeps the barrier skip and the cap exemption.

`ReleaseReplayBarrier` is removed from `controlProducer`, `ControlRouter`, `noopControlRouter`, and `fakeControlRouter`; `Gateway.Publish`'s `AgentFrame_ReplayCompleteAck` arm keeps only its `continue`, so the frame is consumed and never relayed, as `TestPublishRoutesAcksToControlRouterNotUpstream` pins. An empty method named "Release" would mislead.

Latency is unchanged: the `control-source.ts` iterator emits both acks in one `next()` call (`acks.emitReplayCompleteAck(); acks.markApplied(applied.seq);`). The replacement's `AckCursor` starts at `#cursor = 0n`, so `acks.isApplied(seq)` is false for every held seq, and the held ops sit below the lift, so the production ack is `ControlAck{acked_seq: 0, applied_above: [lift]}`. `dispatch` re-emits it on redelivery (`if (acks.isApplied(seq)) { ...; acks.markApplied(seq); return; }`), so a lift-ack batch lost past `PRIORITY_BATCH_RETRY_MS` still releases on the next Control reconnect.

**Bound.** No timer: one that released would resurrect the loss, and one that errored needs a control-lane liveness contract this record does not invent. The hold lives as long as retention: `Retire` drops held ops with the session. The one new case is a lost lift-ack batch, harmless today and held until the Control reconnect above; raise and release are logged.

## Alternatives considered

- **Re-sequence the lift below the retained ops, or re-stamp them above it.** `s.ops` is "ascending by seq; pruned on ack" and `collectBatch` binary-searches it; re-stamping changes the seq an in-flight `ControlAck` names and defeats `acks.isApplied(seq)` dedup.
- **Accept the loss.** DL-081 makes config refresh routine, so the loss recurs on every refresh.
- **Hold in `Start` too.** `Bind` creates fresh state (`p.sessions[sessionID] = &controlSession{}`): nothing is retained and the lift is first (`TestFreshStartSendsReplayCompleteFirst`).
- **Agent-side: buffer pre-barrier immediate ops in `dispatch` instead of refuse-and-ack.** The refusal is the agent's local guard ("invariant 1" in `control-source.ts`, "a belt-and-suspenders on the Runner's hold"); the Runner owns the hold.
- **Drain-time reorder alone: emit replay-path ops before live ops in `collectBatch`, no hold.** The replacement can subscribe before the lift is sent, so its first drain cycle has only live ops to emit.

## Global Constraints

- No wire or behavioral agent change. Comment-only edits to `proto/compass/v1/agent.proto` (regenerated with `moon run compass-proto:gen`) `packages/compass-agent/src/transport/control/ack-cursor.ts`, and `packages/compass-agent/src/transport/control-source.ts` are in scope. `HoldForReplay`, `AckControl`, `serve`, and `collectBatch` keep their signatures; `ReleaseReplayBarrier` is removed.
- The hold is raised only on a served container, after `s.stream.Stop()` returns and before `h.link.StartAgent`; the listener is resolved under `h.mu` and called outside it. Placement in `reloadLocked` covers `Reload` and `refreshOneContainer`. A hold on an unbound or retired session is a no-op (`existingSession` returns false), neither checked nor logged.
- Release rule: `AckControl` clears `held` when `s.held && s.liftSeq != 0 && (s.liftSeq <= s.cursor || above[s.liftSeq] present)`, where `liftSeq` is the seq of the last `AgentControl_ReplayComplete` `send` stamped (`isLift`, never `replayPath`) and `HoldForReplay` clears it. Nothing else clears `held`. Retained ops drain in ascending seq after the lift; nothing is re-stamped.
- No timer, retry, or new bound. A `StartAgent` failure after the hold returns the error and leaves the hold raised, matching today's failed-reload posture (`refreshOneContainer`: "Reload failed: do NOT advance the tracked version ... retries").
- The producer gains a logger through a new `Deps.Log *slog.Logger`; `newControlProducer` defaults nil to `slog.Default()` as `NewConsumer` does. Raise and release log at Info with `session_id`; nothing else changes.
- No database, token, container, or transcript change.

## Open Questions

- **Load-bearing, RIG-4005 — release on lift delivery instead of on ack?** Option A (this record): ack-gated, `held` clears on a `ControlAck` covering `liftSeq`. Option B: `HoldForReplay` records `s.sub` as the hold's generation; `serve`'s send loop clears `held` and calls `signalLocked()` once `sink.Send` succeeds for an `isLift` op on a subscription whose `mine` exceeds it; `liftSeq` and the `AckControl` change go. Both remove the `ReplayCompleteAck` release. The generation gate closes B's residual, a not-yet-exited predecessor drainer sending the lift on its dead stream. B covers reload: the replacement's barrier opens at decode (`dispatch`: `case "replayComplete": { replayComplete = true; ...`) and `serve` sends in order on one stream. The remaining difference: A holds until the next Control reconnect when the lift-ack batch is lost; B releases at delivery, before the agent applies the lift. Recommendation: A, because release stays on the agent's confirmed apply, as `packages/compass-agent/src/control.ts` states ("the Runner holds live prompt/steer until the agent acks ReplayComplete"). The plan above is A.
- **Load-bearing, RIG-4029 — the podman survivor.** The DL-372 record measured on podman 5.8.6 (the `SelectBackend` default) that `Stop` leaves the pre-reload agent alive and subscribed; apple-container shares `spawnStreaming` in `go/internal/runtime/clispawn.go`, which kills only the exec client (`cmd.Cancel = func() error { return cmd.Process.Kill() }`). That survivor can apply and ack the new lift before the replacement subscribes, releasing the hold and consuming the held ops: today's behavior, not a regression. RIG-4029's option (1), displacing the pre-reload subscription before the lift, is what makes this record's guarantee hold there. Not resolved here.
- **Deferred, non-load-bearing — an agent that never acks the lift.** Held with the hold, refused without it. A liveness deadline for the control lane is a separate record.
