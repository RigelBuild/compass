# Reload held control ops

Tracker: RIG-3923. Freezes on merge.

Depends on the reload replay barrier record (`docs/designs/agent/reload-replay-barrier/design.md`, DL-372), which makes `reloadLocked` re-send `AgentControl{replay_complete}` after the stream swap. This record does not restate it.

## Problem / Intent

`reloadLocked` in `go/internal/runner/host.go` SIGKILLs the running agent (`s.stream.Stop()`) and relaunches one into the same session. A live op the old agent received but never acked stays retained above the cursor, and `controlProducer.serve` in `go/internal/runner/gateway/control.go` starts every new subscription there: `sent := s.cursor` ("everything retained above it is owed to this subscription, whether it was never sent or sent to a predecessor that never acked"). The DL-372 lift carries the highest seq and `collectBatch` walks `s.ops` ascending, so the retained ops drain first, into the replacement's closed barrier. `dispatch` in `packages/compass-agent/src/transport/control-source.ts` refuses and acks each one ("live immediate op before ReplayComplete — refused by replay barrier", then `acks.markApplied(seq)`), and the ack prunes it (`AckControl`: `if r.seq <= s.cursor { continue }`). A deliver, steer, or forge notification in flight across a config refresh is lost with no error anywhere. `Reload` and `refreshOneContainer` both reach this path through `reloadLocked`.

## Approach

**Hold.** Raise the producer's existing replay barrier from `reloadLocked`, after `s.stream.Stop()` returns and before `h.link.StartAgent`, on served containers only. `controlProducer.HoldForReplay` was built for this and has no production caller ("Raised by the lifecycle when it restarts an agent into an existing session ... No production caller yet"). While `s.held` is set, `collectBatch` skips live ops (`if s.held && !replayPath(r.op) { continue }`) and `send` still wakes the drainer for the lift (`if !s.held || replayPath(stamped) { s.signalLocked() }`), so the lift drains through the hold, the retained ops wait behind it, and after release they drain in seq order through `serve`'s cursor-plus-set watermark. The hold must precede `StartAgent`: the lift is sent after `StartAgent` returns, so the replacement can subscribe before the lift exists. It reaches the producer through a new `SocketListener.HoldForReplay`, the nil-safe delegation `BindSession` uses (`if l.control == nil { return }`), resolved under `h.mu` and called outside it as the DL-372 helper does.

**Release is keyed to the lift.** `send` records `s.liftSeq = s.nextSeq` for every replay-path op, held or not; `HoldForReplay` clears it. Two acks release, and both require `s.held && s.liftSeq != 0`:

- `ReplayCompleteAck`, routed by `Gateway.Publish` in `go/internal/runner/gateway/publish.go` (`case *compassv1internal.AgentFrame_ReplayCompleteAck: g.control.ReleaseReplayBarrier(sessionID)`). The agent emits it apply-then-ack in the `control-source.ts` iterator (`if (applied.op.kind === "replayComplete") acks.emitReplayCompleteAck(); acks.markApplied(applied.seq);`). `ReleaseReplayBarrier` becomes a no-op while held and no lift has been sent since the hold (`s.liftSeq == 0`): the frame carries no identity (`ReplayCompleteAckSchema, {}`), and a killed predecessor's startup ack can be read by the Publish handler after the hold is raised. Unconditional release would clear `held` before the lift is sent and the replacement would drain the retained ops ahead of it — the loss this record removes. A stale ack read after the lift is sent would still release, but that frame would have to sit unread through `Stop` and `StartAgent`.
- `ControlAck` covering the lift: `AckControl` releases when `s.liftSeq <= s.cursor` or `above[s.liftSeq]` is present. The replacement's cursor is `0` and the held ops sit below the lift, so the production shape is `ControlAck{acked_seq: 0, applied_above: [lift]}` — the `applied_above` arm is the primary path. This ack is re-emitted on redelivery (`dispatch`: `if (acks.isApplied(seq)) { ...; acks.markApplied(seq); return; }`) and `ReplayCompleteAck` is not, so a priority batch that exhausts `PRIORITY_BATCH_RETRY_MS` (`[50, 200, 800]`, then "counted definitively failed") followed by a Control reconnect still releases.

**Bound.** No timer: one that released would resurrect the loss, and one that errored needs a control-lane liveness contract this record does not invent. The hold's lifetime is retention's. `Retire` (`delete(p.sessions, sessionID)` ... `s.ops = nil`, reached from `Stop` or `Remove`) is a loss bound: it drops held ops with the session. `maxRetainedOps = 4096` fails a live `Send` with `CodeResourceExhausted` back to `Deliver`, but a low-traffic session never reaches it, so it is not an operator signal. The hold changes one case: a lost lift-ack batch is harmless today (the agent still receives and applies live ops) and becomes held-until-Control-reconnect, which the `ControlAck` release mitigates. A `StartAgent` failure leaves the hold raised; on the podman tier a retry fails at `s.stream.Stop()` (`ChildHandle.Terminate` in `go/internal/runtime/podman.go` ends in `return h.cmd.Wait()`, and a second `Wait` errors), so a retry never reaches the hold there. No agent exists in that state with or without the hold. Observability: `HoldForReplay` logs the raise and the release path logs the `held` true→false transition, so a wedged hold is visible without a timer.

## Alternatives considered

- **Re-sequence the lift below the retained ops, or re-stamp them above it.** `s.ops` is "ascending by seq; pruned on ack" and `collectBatch` binary-searches it; re-stamping changes the seq an in-flight `ControlAck` names and defeats `acks.isApplied(seq)` dedup. The barrier exists so ordering does not change.
- **Accept the loss.** `Deliver` returns nil ("success is confirmed later by delivery_ack"), so the Server counts the op as dispatched; DL-081 makes config refresh routine. Routine silent loss, one call to fix.
- **Hold in `Start` too.** `Bind` creates fresh state (`p.sessions[sessionID] = &controlSession{}`): nothing is retained and the lift is first (`TestFreshStartSendsReplayCompleteFirst`).
- **Agent-side: buffer pre-barrier immediate ops in `dispatch` instead of refuse-and-ack.** Invariant 1 is pinned in the agent, and a buffered late deliver would apply ahead of a future transcript replay.
- **Drain-time reorder alone: emit replay-path ops before live ops in `collectBatch`, no hold.** The replacement can subscribe before the lift is sent, so its first drain cycle has only live ops to emit. Holding before `StartAgent` is what closes that race.

## Global Constraints

- No proto, wire, or agent-side change. `HoldForReplay`, `ReleaseReplayBarrier`, `AckControl`, `serve`, and `collectBatch` keep their signatures.
- The hold is raised only on a served container, after `s.stream.Stop()` returns and before `h.link.StartAgent`; the listener is resolved under `h.mu` and called outside it. Placement in `reloadLocked` covers `Reload` and `refreshOneContainer`. A hold on an unbound or retired session is a no-op (`existingSession` returns false), neither checked nor logged by the host.
- Release requires `s.held && s.liftSeq != 0`, where `liftSeq` is the seq of the last replay-path op `send` stamped and `HoldForReplay` clears it. Retained ops drain in ascending seq after the lift; nothing is re-stamped.
- No timer, retry, or new bound. A `StartAgent` failure after the hold returns the error and leaves the hold raised, matching today's failed-reload posture (`refreshOneContainer`: "Reload failed: do NOT advance the tracked version ... retries").
- The producer gains a logger through a new `Deps.Log *slog.Logger` (nil defaults to `slog.DiscardHandler`); raise and release log at Info with `session_id`. No other logging change.
- No database, token, container, or transcript change.

## Open Questions

- **OQ-1, load-bearing, routed to the operator as RIG-4005: release on lift delivery instead of on ack?** Option A (this record): ack-gated — `held` clears on the replacement's `ReplayCompleteAck` or on a `ControlAck` covering `liftSeq`. Option B: clear `held` under `s.mu` in `serve`'s send loop once `sink.Send` succeeds for a replay-path op, then `signalLocked()`; drop `liftSeq` and the `AckControl` change. B is sufficient for reload: the replacement's barrier opens at decode (`dispatch`: `case "replayComplete": { replayComplete = true; ...`) and `serve` sends batch ops in order on one stream, so lift-on-the-wire is lift-decoded-first; B has no stale-ack race and no held-until-reconnect case, and a Control drop after the lift is covered by redelivery from the cursor. A keeps the frozen protocol text in `packages/compass-agent/src/transport/control.ts` ("the Runner holds live prompt/steer until the agent acks ReplayComplete"), which a future `TranscriptReplay` needs because its live ops must wait for apply, not decode. Recommendation: keep A. Not resolved here; the plan above is A.
- **OQ-2, resolved — predecessor liveness at the hold.** "No agent alive after `Stop`" is an assumption inherited from `AgentStream.Stop` in `go/internal/runner/agent_exec.go` (`s.exec.Process.Terminate()`). It holds on the host tier (`HostRuntime.ExecStreaming` in `go/internal/runtime/host_backend.go`: `killGroup(proc.pgid, syscall.SIGKILL)`) and the microVM tier (`MicroVMRuntime.ExecStreaming` in `go/internal/runtime/microvm_lifecycle.go`: `gs.Kill(int(syscall.SIGKILL))`). On podman, `spawnStreaming` in `go/internal/runtime/clispawn.go` sets `cmd.Cancel = func() error { return cmd.Process.Kill() }`, which kills the `podman exec` client; the repo does not show whether the in-container agent dies with it. A surviving predecessor would receive and ack the new lift and consume the held ops — today's zombie behavior, not a regression.
- **OQ-3, resolved — agent-side dedup.** The replacement's `AckCursor` starts at `#cursor = 0n`, so `acks.isApplied(seq)` is false for every held seq.
- **OQ-4, deferred — an agent that never acks the lift.** Held with the hold, refused without it. A liveness deadline for the control lane is a separate record.
